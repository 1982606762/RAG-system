# 可重建索引：向量状态、检查点与模型隔离

这次值得补一篇笔记：现有《数据导入：幂等、事务与版本留存》已解释身份、哈希和事务，但没有覆盖“数据库外的云调用做到一半失败，怎样保留成果”。本材料对应本次向量入库代码，正式笔记仍由你手工整理。

## 是什么：原资料与派生结果分别管理

向量是根据片段文本和模型生成的派生数据。保留原件、blocks、chunks，就可以重建它；向量调用失败，不代表原资料不可用。

本次 `documents/service.py` 先提交解析与分块结果，再调用 `embeddings/service.py`。因此同一文档可以同时处于：

| 状态 | 含义 |
| --- | --- |
| `document.status = ready` | 可以阅读和关键词搜索。 |
| `embedding.status = failed` | 向量任务未完成，成功子段仍可保留。 |

例如生产 Vertex API 尚未启用，或调用遇到配额限制，应该记录独立错误并允许继续；不应撤销已完成的解析。这是本次状态分离解决的实际问题。当前真实 Vertex 调用仍待 API/IAM 配置后验收，语义搜索属于下一阶段。

## 如何使用：小事务保存检查点

检查点就是“哪些工作已经可靠落库”的记录。`embedding_parts` 保存子段范围、输入摘要、来源、向量和 token 数；向量尚为空的子段需要继续处理。简化流程如下：

```python
for part in validated_parts:
    if part.completed:  # 已确认同 profile、同实际输入
        continue
    vector = cloud.embed(part.text)  # 不放进数据库事务
    save_vector(part, vector)        # 单独提交检查点
```

云请求可能很慢，数据库事务也无法回滚一次已经完成的云调用，所以不能靠包住整个循环来获得跨系统原子性。本次仍持有 session advisory lock 串行入库，但没有在等待云响应时保持一笔数据库事务。

超过模型限制时，`split_part()` 在一个短事务里删除未完成的父段、写入两段计划，避免留下半张分段清单。两个子段随后分别调用和落库。

测试用 `abcd` 人为模拟超限：先拆成 `ab`、`cd`，保存 `ab` 后让 `cd` 失败；再次执行只请求 `cd`。真实限制按 tokens 判断，不是四个字符。本次设置 `autoTruncate=false`，并检查响应的 `truncated` 与 `token_count`，防止“成功返回，却漏掉尾部正文”。文档侧指定 `RETRIEVAL_DOCUMENT`。[Google REST 文档](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/model-reference/text-embeddings-api)

## 怎样判断旧成果还能复用

需要同时核对两类身份：

- **计算规则**：`Profile.key` 把项目、区域、模型资源、任务类型、768 维和输入策略版本组成摘要。换模型或策略，就进入另一套 profile。
- **实际输入**：`chunk_hash` 检查父片段，`input_hash` 检查真正发送的子串。`valid_parts()` 还检查分段有序、无缺口，并覆盖整个片段。

例如模型 A 已完成，切到 B 时不能因为“都有 768 个数字”就复用 A。保留旧 profile 供核对，当前状态只读取 B。这里的 profile 是本项目选择的隔离边界；区域或项目改变，即使模型相同，也会保守地重新计算。

重新解析会删除、替换 chunks；外键 `ON DELETE CASCADE` 删除关联的全部模型向量，进度重置为 pending。这样不用逐个记住哪里缓存了旧片段。只改变模型时，则无需重新上传或调用 Document AI。

## 何时使用，哪些保证不能夸大

向量、缩略图、转录、批量翻译等“可以从原资料重做”的耗时任务，都适合独立状态和检查点。个人规模先用串行处理、时间预算与手动继续即可；当前没有自动重试或后台队列。

这不保证云调用 exactly once：云端已完成、但响应丢失或落库前进程退出，重试仍可能再次调用并产生费用。保证的是已保存成果可复用，数据库唯一键防止同一分段出现重复记录。哈希判断内容相同，不证明哪个版本更新，也不证明来源可信。

## 学习范围与理解检查

现在必须理解：两个 ready 的意义、检查点何时算完成、云调用与数据库事务的边界、profile 与输入摘要分别检查什么。以后再深入任务队列、退避重试、并行调度及索引版本切换。

1. 云端返回成功后、`save_vector()` 前断电，下次可能重复哪一步？为什么唯一键不能避免这次云调用？
2. 一段已保存三个子段，其中一个失败；模型不变但正文改变一个字，为什么不能直接沿用其余两个子段？结合 `valid_parts()` 和重解析的外键级联解释。
