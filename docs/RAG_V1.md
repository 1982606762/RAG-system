# 个人文件 RAG 第一版设计

已实现原文定位、向量入库、语义搜索和可保存的自然语言问答。基础能力见 [MVP 说明](MVP.md)，解析和索引细节见 [原文定位](ORIGINAL_LOCATIONS.md) 和 [向量入库](EMBEDDINGS.md)。

## 用户可以做什么

个人文件库保存 PDF、TXT、Markdown 和扫描发票等资料。主人可以用自己的措辞搜索，看到相关片段，也可以直接提出问题，由系统阅读一份或多份资料，返回答案、明细或表格。点击引用可查看支持该结论的原文。文件按内容去重。遇到模糊金额、相互矛盾的条款或不完整的资料，列出各自证据，交给主人判断。

第一版只读查询已上传的文件。允许把原件、文本片段和问题发给 Google 处理，按联网使用设计。用户默认让系统自动决定查询深度，也可以选择“深入核对”。

## 数据如何流动

| 环节 | 实现逻辑 |
|---|---|
| 采集与解析（已有） | 后端保存原件和内容摘要。配置 Google Document AI 后由 Layout Parser 解析；生成带来源的 blocks，再按结构生成 chunks。PostgreSQL 保存元数据、文本及片段到原文块的映射。 |
| 向量化（已实现，云端待配置） | 通过 Google Cloud 的 Vertex AI 入口调用 gemini-embedding-001，为每个片段使用 RETRIEVAL_DOCUMENT，输出 768 维并归一化。语义搜索使用同一模型、维度和 RETRIEVAL_QUERY。模型区域和调用权限可单独配置，可复用已有 ADC 认证方式。 |
| 检索（已实现） | 默认关键词搜索可匹配型号和编号。切换到语义搜索后，pgvector 在当前配置下已完成向量化的资料中做精确余弦距离排序。同一片段有多个向量时，以最近的子段距离排序，每个片段只出现一次。两种模式统一返回正文、文档与片段标识、章节及来源位置。 |
| 问答（已实现） | Gemini 可调用关键词或语义搜索，并为已找到的片段读取前后文。后端从本次实际读取的资料核对引用 ID 和原文位置。 |
| 阅读（待扩展） | 搜索结果和答案引用共用阅读器。PDF 有可靠坐标时高亮段落或表格行，否则直接打开对应页。TXT、Markdown 按原文件的行或字符范围定位；单张扫描图片可打开原图并展示识别文本。 |

### 向量与原件的生命周期

沿用 documents、blocks、chunks。新增向量记录，关联文档和片段，并记录模型、维度及实际输入的摘要。当前分块上限按字符计算；调用时检查模型 token 限制，超限片段应细分并保留子段来源，避免静默截断。原件是长期保存的数据，向量可从已有片段重建。

文档 ready 继续表示可以阅读和关键词搜索。另行记录向量化进度及错误；单独重试或回填旧文档时，跳过相同模型下已完成且输入未变的片段。重新解析后，使旧片段的向量失效。上传重试、重复导入、模型切换都不能让检索混用过期向量。

### 答案如何核对

自动模式按问题选择阅读范围。简短条款问题可以只读相关段落；跨文件或整年汇总需要查找相关文件、扩大阅读范围、核对日期覆盖与重复记录，不能把相似度前几条当作完整清单。深入核对模式主动阅读上下文、比对来源，并列出差异与覆盖缺口。两种模式都展示依据。

例如问“今年一共交了多少车贷”，若两份合同分别列有 1–3 月和 4–12 月计划，先识别年份、截止日及币种，提取对应条目，用确定性计算加总，再列出各段金额及原文引用。只有合同计划时，可以回答“按合同推算，截至该日应付……”。有实付凭证时说明它能确认的金额；数据缺失时列明小计范围。这是通用的跨文档阅读能力，第一版无需专门的车贷或发票业务表。

当前问答使用独立的 Gemini 模型，默认 `gemini-3.1-flash-lite`、`global`，项目和 Google ADC 默认沿用向量配置。可用 `VERTEX_ANSWER_PROJECT`、`VERTEX_ANSWER_LOCATION` 和 `VERTEX_ANSWER_MODEL` 分别覆盖。自动和深入核对分别最多有四轮和六轮检索。深入核对至少执行两轮工具调用；两种模式都限制片段覆盖范围。引用核验保证引用可以定位至本次检索到的片段。金额汇总由模型根据命中的内容组织，仍应通过引用复核算术和覆盖范围。

## 实施顺序与验收

| 阶段 | 工作位置与交付 | 验收场景 |
|---|---|---|
| 1. 原文定位 | 扩展 app/documents/ 的解析和来源映射，以及 frontend/src/components/DocumentReader.tsx。现有块内偏移是解析文本位置，需额外保存到原文件位置的映射；旧文件缺位置时提供可用的回退。 | 从结果打开 TXT、MD 的对应原段落；从 PDF 引用打开相关页，有坐标时高亮。 |
| 2. 向量入库 | 在 app/db/migrations/ 增加迁移，Compose 使用兼容现有 PostgreSQL 16 数据卷的 pgvector 镜像。在分块后接向量化，app/cli.py 提供旧资料补算入口。 | 新文件生成向量；旧片段无需重新上传或调用 Document AI 即可补算。模拟调用中断，文档仍可阅读，重试后无重复。 |
| 3. 语义搜索 | 扩展 app/api/search.py 和搜索面板。个人库先用精确向量搜索，根据真实查询延迟和命中质量决定是否增加 HNSW 或融合排序。 | 用不同于原文措辞的问题找到目标段落；用精确编号仍能找到原文。 |
| 4. 自然语言问答 | 在现有 owner 认证下增加问答接口与交互界面，复用检索、原文读取和引用定位。 | 两份文件能组成带明细和引用的答案；加入重复凭证、冲突金额或缺失月份后，结果能指出证据边界。两种查询深度均可用。 |

### 会话

网页在 PostgreSQL 保存会话。追问时，Gemini 接收最近三轮的简短问答和被引用文档的临时编号，可据此限定本次搜索范围。历史回答只用于理解追问，每轮重新查找证据。刷新可继续上次会话，删除会话会同时删除其问答记录。

## 后续扩展

主人完成其他项目后，统一问答入口可调用其只读 MCP 工具。比如“今年每个月在 Føtex 买了多少钱，请绘制表格”，由 cardless 按年份、商家查询完整交易并按月聚合；若数据已足够，直接用返回值制表。库存问题由 receipe 查询当前冰箱库存。跨来源问题才组合相应结果，同时注明来源。未来的写入操作另行设计。外部服务可用性不影响第一版验收。

解析、生成向量和生成答案各自使用独立调用接口。未来购买硬件后可逐项换成本地实现；更换回答模型可复用文档向量，更换 embedding 模型则重建索引并同步切换查询模型。现阶段不要求部署本地模型或支持断网。
